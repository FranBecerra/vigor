## Source-backed programming audit

- **Rest:** `restDurationFor` currently returns 150/120/90 seconds. [Singer et al., 2024](https://pubmed.ncbi.nlm.nih.gov/39205815/) reports a possible small hypertrophy advantage of longer versus very short rests, with uncertainty; it does not establish a universal 120-second minimum or a decisive 90-versus-120 rule. A 120-second isolation starting default is a reasonable product proposal, not a validated optimum. Recompute capacity rather than fitting the same sets into an unchanged time estimate. Respect explicit athlete rest overrides.
- **Bands:** `abduccion-cadera-banda` already has lower stretch/profile/progression scores than the machine (1/2/1 versus 4/5/4). [Hostler et al., 2001](https://pubmed.ncbi.nlm.nih.gov/11822469/) studies adaptations to elastic resistance, not a direct hypertrophy comparison of band hip abduction with a machine. Do not equate strength/EMG findings or a general elastic-training study with proof of this exact exercise's superiority. Reproduce why the optimizer picks it with the athlete's eligible equipment, region coverage and exclusions before changing selection. Prefer stable/progressible alternatives when actually eligible; retain a bands-only fallback.
- **Order:** `orderSessionExercises` sorts anchor compounds with >=3 sets, other compounds and isolation; then primary-muscle priority, primary/secondary profile, descending set count, descending estimated fatigue and stable ID. This is an implementation heuristic, not a universal best sequence.
- **Split:** placement costs explicitly allow focus mismatch when time/per-muscle caps bind. Presentation focus is normalized in some paths, but explicit split preservation can keep original labels. Reproduce the upper/lower scenario and repair allocation/transparent limitation reporting, not just rename every spillover day.
- **Fatigue:** the selection default permits four sets; there is no universal fatigue-specific minus-one contract. The catalogue's `systemicFatigueCost` is inverse-coded (larger is lower cost). Test dose, weekly distribution, stable alternatives and sequence together before adding a cap. Four sets are not inherently wrong solely from an ordinal score.

Official implementation references checked: [Expo SDK 57](https://docs.expo.dev/versions/v57.0.0/) and the installed gesture-handler Pan/native scroll contracts. No dependency or infrastructure change.
