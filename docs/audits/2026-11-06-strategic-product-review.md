# Vigor strategic product review: implementation audit

Date: 2026-11-06. This is a static audit of the current repository. The PRD defines the product requirements. Status below describes production call paths found in the checkout. A pure helper, a fixture or a documented design is not evidence of an end-to-end feature.

## Data and integrity issues to resolve before adaptive writes

- **Target versus actual effort.** [Workout execution](../../src/services/training/workoutExecution.ts) and [history correction](../../src/services/training/historyEditing.ts) distinguish athlete input, inherited target and failure. Bio uses explicit effort provenance for comparable trends. The history RIR replanner currently accepts a valid numeric actual without the same provenance gate. Define which source each recommendation accepts and how legacy missing provenance is handled.
- **Historical plan versus current prescription.** Revisions, overrides, exercise snapshots and recorded sets support reconstruction but serve different purposes. Planned versus performed comparisons need a stable occurrence identity and an explicit effective prescription. Cover edits, skips, partial sessions, substitutions, legacy snapshots and variable civil-day windows. Distinguish skipped, missing and incomplete work from completed work.
- **Ownership, linkage and retries.** Generated strength creates routine, mesocycle and then updates the active pointer in separate writes. Manual creation writes the mesocycle first and reuses its draft identity on retry. Hybrid creation has a transaction with an exact retry receipt. Audit partial writes, stale pointers, concurrent closes, offline retries and immutable history before choosing a successor write contract. A transaction in one flow is not evidence of offline successor behavior.
- **Analysis coverage.** Set count, performance, session effort, optional recovery and local discomfort are available with different coverage. Movement-pattern trends, complete plan-versus-actual comparisons, consistent historical strength/cardio load alignment and a reliable joint outcome model remain open. Missing measures and unequal microcycle lengths require explicit handling.
- **Decision trace.** Existing traces and guards are feature-specific. There is no common persisted record that explains the evidence cutoff, comparison context, rationale, uncertainty, and athlete decision for a longitudinal proposal. Determine what must be stored, what can be reconstructed, and what must remain device local before a schema change.

## Candidate implementation order

1. Establish scenario fixtures and failure/retry coverage across the current generated, manual and hybrid paths.
2. Deliver an athlete-reviewed successor for an existing strength routine, starting with continuity and explicitly selected assistance.
3. Extract reusable indicators with comparability and uncertainty, then integrate them into plan proposals.
4. Extend the same evidence and review contract to hybrid changes and successor blocks. Keep current hybrid work moving where it does not depend on this contract.

This review changed documentation only. It does not claim a new recommendation engine or physical-device verification.
